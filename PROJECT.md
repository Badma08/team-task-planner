# PROJECT.md

## Название

Team Task Planner — MVP командного планировщика задач.

## Цель MVP

Сделать веб-приложение для небольшой команды, где участники могут планировать работу по проектам, назначать задачи, отслеживать статусы и видеть дедлайны в календаре.

## Продуктовая рамка

MVP должен решать базовые задачи командного планирования без лишней автоматизации и без AI-функций в пользовательском интерфейсе.

## Основные сценарии

1. Пользователь входит в приложение.
2. Пользователь выбирает команду.
3. Пользователь создает проект внутри команды.
4. Пользователь создает задачу в проекте.
5. Пользователь назначает исполнителя и дедлайн.
6. Участники меняют статус задачи.
7. Участники оставляют комментарии к задаче.
8. Команда смотрит задачи списком, на доске и в календаре.

## Основные разделы приложения

- Дашборд: краткая сводка по задачам, проектам и ближайшим дедлайнам.
- Задачи: список задач с фильтрами и сортировкой.
- Доска: Kanban-представление задач по статусам.
- Календарь: задачи, отображенные по `due_date`.
- Проекты: список проектов команды и страницы отдельных проектов.
- Команда: участники команды и их роли.
- Настройки: базовые настройки команды и профиля.

## Ограничения MVP

- Не добавлять AI-функции в интерфейс продукта.
- Не добавлять интеграции с внешними календарями в MVP.
- Не добавлять сложную аналитику, отчеты, billing или marketplace.
- Не подключать Supabase/PostgreSQL, пока конкретная задача явно не требует работу с базой данных.

## Технические принципы

- Использовать Next.js App Router.
- Писать код на TypeScript.
- Делать UI на Tailwind CSS и shadcn/ui.
- Хранить будущие командные данные с обязательной привязкой к `team_id`.
- Делать изменения небольшими, проверяемыми шагами.
